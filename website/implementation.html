Implementation and audit

How does a mathematical claim become a reproducible research result?

This page connects theorem statements to executable mathematics, tests, figures, and provenance. It is the engineering layer of the research, not a separate source of scientific meaning.

The pipeline

Five stages connect an idea to an auditable result

Readers can stop at any stage or continue all the way to the source code.

1

Question and assumptions

State exactly what is being tested and what must be true for the result to apply.

2

Formal result

3

Executable object

Implement the declared mathematical object without silently changing the theorem.

4

Verification

Use tests, exact arithmetic where appropriate, and consistency checks to catch implementation or publication errors.

5

Publication record

Connect the theorem, code, tests, figure, provenance, and scientific boundary through stable links.

Stage 1

Start with the scientific question, not the code

The implementation should never decide what the theorem means. The theorem page defines the objects, assumptions, and permitted conclusion first.

That makes it possible to compare the source code with a fixed mathematical target instead of interpreting whatever the program happens to output.

Stage 2

Make the mathematics explicit enough to audit

A mature result should distinguish the theorem from supporting examples, standard identities, numerical demonstrations, and modeling assumptions.

When computation is part of the proof strategy, the direction of every numerical bound matters. A useful numerical estimate is not automatically a certificate.

Stage 3

Turn the formal object into executable mathematics

Repository source modules live under src/consciousness_bridge/. Their job is to implement declared mathematical constructions, estimators, optimization procedures, certificates, and exact finite families.

Code is treated as an implementation of a scientific object, not as a substitute for defining that object.

Stage 4

Try to break the implementation

Regression tests protect exact values, family counts, edge cases, scientific boundaries, documentation consistency, and publication contracts.

The purpose is not only to show that one example runs. It is to make accidental changes visible before they become part of the public research record.

Stage 5

Publish the result as a connected record

A theorem should not be isolated from its code, tests, figure, and source history. The repository links these pieces so a reader can move from explanation to proof to reproduction without guessing filenames.

Figures are also treated as research artifacts. Their captions and descriptions state what they show, how to read them, and what they do not establish.

Scientific boundary

Executable mathematics is not experiential evidence by itself

The code implements declared mathematical objects and tests under stated assumptions. Successful execution does not identify consciousness or complete the physical to experiential bridge.
