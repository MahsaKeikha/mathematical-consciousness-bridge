A five-minute first read

Start with the question, not the 88 propositions.

The project asks what would have to be true before a physical description of a system could support a scientifically testable claim about an independently specified experience-related target. The mathematics comes later. First comes the logic of what has to be tested.

The idea

Before asking what consciousness is, ask what a scientific bridge would have to survive.

The repository deliberately separates problems that are often compressed into one claim. A physical description can be precise and predictive yet still omit a distinction relevant to an independent target. A target can look meaningful yet be circularly built from the same variables being tested. A model can recover parameters and still be wrong. A numerical fit can look impressive and still lack a valid finite-data certificate.

01

Define the physical description

State which variables, dynamics, interventions, time scales, spatial scales, and boundaries are actually included.

02

Define the target independently

Do not manufacture the experience-related target from the same physical descriptor and then treat it as independent evidence.

03

Validate the measurement

Ask whether reports, labels, behavior, or other observations preserve the target distinction reliably enough to support inference.

04

Test the model itself

Parameter recovery is not model validation. The declared model needs constraints that can actually fail.

05

Include finite-data uncertainty

A visible mismatch is not enough. Statistical and numerical uncertainty must be certified in the correct direction.

06

Keep the bridge open until earned

None of the earlier steps automatically identifies a physical quantity or latent variable with experience.

The most important boundary

The repository does not claim that consciousness has been derived from physics.

A theorem about a declared model is not automatically a theorem about consciousness. A failed descriptor is not proof of nonphysical consciousness. A latent variable is not automatically experience. A model that survives a test is not therefore uniquely correct. The physical-to-experiential bridge remains open.

Six recurring terms

Learn these once and the rest of the repository becomes much easier to read.

Physical descriptor

The declared physical information used by a bridge claim.

Target

An independently specified distinction the descriptor is being asked to explain.

Latent state

An unobserved model variable. It has no experiential meaning merely because it is mathematically useful.

Observation channel

The measurement process linking an underlying target to reports, labels, behavior, or other observations.

Rejection

A certificate that the declared model is incompatible under stated assumptions. It is not an ontological conclusion.

Bridge claim

The still-open step connecting a sufficiently complete physical description to experiential structure.

Current theorem frontier · P88

Can a discovered incompatibility survive independent validation?

P87 can search 39,600 exact four-event parity functionals. P88 addresses the selection problem by allowing discovery to choose a P75 box and one P87 functional, then freezing that pair before fresh validation data are examined.

What P88 establishes

Conditional on genuine discovery/validation independence, one frozen scalar functional can be tested without paying a 39,600-way validation union bound.

For the stored exact witness, the P79-certified minimum held-out size for the specified gap is 1063. With n = 2400 and alpha = 0.05, the certificate gives a positive lower-confidence bound on distance from the P75 laws inside the frozen box.

Research origin

One conceptual starting point, followed by a distinct mathematical program.

An early line of inquiry that helped motivate this project came from studying Max Tegmark's Consciousness as a State of Matter (2015), including its discussion of subsystem structure, factorization, information, integration, independence, and dynamics. The present repository develops its own proposition sequence, assumptions, derivations, implementations, and tests.
